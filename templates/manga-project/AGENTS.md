# 漫画プロジェクトの作業ルール

- NovelAIで有効なOpus契約を使う場合、１回１枚、28ステップ以下（V5は初期値23、V4.5以前は28）を既定とする。生成寸法は使用ツールに合わせる共通のページ設定に従い、生成実寸に枠と最終PNGを合わせる。採用寸法を含む全設定、V5の利用上限・参照等の追加料金を実行前に確認し、有料利用の明示指示なしにAnlasを消費する生成へ進まない。詳細・出典は `docs/knowledge/ai-production.md` のOpus節。他の生成環境には一律適用しない。

- 最初の作業時はOPTIONの「日本語推敲スキル」を解決して `scripts/Initialize-OptionalSkills.ps1` を実行する。有効なら作品内へ自動導入し、無効なら外部取得しない。再開・後日の有効化でも導入状態を確認する。手順は `docs/knowledge/optional-skills.md`。作成元のキットや雛形を読んでいるだけの場合は実行しない。
- 選択したスキルの取得に必要なGitがなければ、インストールしてよいかユーザーへ必ず確認する。Geminiを使うスキルは、環境が利用可能と分かっていても、文章の送信とGeminiの利用枠を消費してよいか導入前に必ず確認する。OPTIONの有効化だけではこの許可にならない。実際の明示回答がある場合だけ初期化処理へ `-GeminiConsent Granted` と回答・範囲を渡す。未回答・拒否なら取得・導入・試験呼び出しをせず、通常の制作を続ける。
- 推敲スキルは採用中のスキルと指定対象だけに使う。無効化・許可撤回後は、導入済みでも使わない。許可は同じ作品・固定版・指定範囲に限って保持し、範囲拡大や版変更は確認する。利用可能なGemini環境や他作品の許可から承諾記録を作らない。

- 基本の依頼はキャラ・あらすじ・ページ数の指定。追加設定なしでWeb用のページ漫画をPNGまで制作する。未指定の詳細は既定値と制作判断で補い、OPTIONの全項目や印刷仕様への回答を開始条件にしない。掲載形式・基本枠は `docs/knowledge/page-layout.md`、印刷を選ぶ場合だけ `PRINT-OPTION.md` を使う。
- 寸法は「生成時の希望／生成後の実寸 → 枠配置 → 最終PNG」を区別し、幅×高さで案内する。既定は１ページ全体の生成画像の実寸に枠を合わせ、同じ寸法でPNGにする。サイズ変更時は余白・線幅も基準値から換算する。同梱枠素材の2000×3000pxを生成・書き出しの指定として案内しない。
- 時間の切替・画面密度・動作のつながりをネームとPNGで点検する。文字の採用設定は `docs/production/DIALOGUE.md`、作品内で再利用する修正条件は `docs/reviews/NAME-REVIEW.md` に集約し、次ページで条件が合うか確認する。追加の文体推敲はOPTIONで選んだ対象だけに行う。

- ここは `New-MangaProject.ps1` で作成された作品プロジェクト。作業フォルダがこの作品のルートであることを `project.json` とともに確認し、ここで漫画を制作する。配布元の制作キットへ戻って描いたり、さらに新規プロジェクトを作り直したりしない。キット内での例外制作を示すファイルは不要。雛形原本として読んでいる段階では、配布元の `AGENTS.md` に従って個別プロジェクトを作る。
- 漫画はまずPNGプレビューを提示し、修正があれば反映・再提示して、ユーザーに修正がないことを確認する。PSD作成の指示がない場合はいったん作らず、作るか聞いて回答を待つ。既にPSD作成の指示がある場合は再確認せず、PNGの修正確認後に作成・検証・引き渡しへ進む。返答がない状態を「修正なし」や作成指示とみなさない。PSDを依頼された場合の完成条件は `docs/knowledge/psd-handoff.md`。原則、人間がCLIP STUDIO PAINTで仕上げてから外部公開する。CBZはユーザーの明示指定がある場合だけ作成する。
- 説明・ノウハウ・記入項目・引き継ぎ・レイヤー名は日本語にする。日本語として通じるカタカナ語は使用可。製品名、出典URL、パス、機械用識別子は維持する。

- 一つのプロジェクトで一つの漫画を制作する。作品設定は `docs/story/`、整理した判断・出典・進捗は `docs/` に残す。
- 再開時は `docs/PROGRESS.md` と `docs/PLAN.md` を読む。着手・判断変更・生成/検証・中断の節目に現在地と次の行動を更新する。
- 制作開始時は `OPTION.md` を読み、ファイルがない・項目が未記載なら `docs/knowledge/project-options.md` の既定値を使う。ユーザー指定を優先し、コマ割りの採用率を含む実効設定を一度説明して進める。採用値・出所・ファイルの有無とSHA-256を進捗に残す。
- 再開時と各工程の着手前に `OPTION.md` の変更を確認する。開始後に値が変わっていたら意図を確認し、回答までその変更が関係する作業への適用を保留する。会話で指示済みの変更は再質問しない。欠落時の既定値・削除・確認待ちの扱いは `docs/knowledge/project-options.md` に従い、採用した設定をこのファイルの既定方針へ反映する。詳細資料は必要なときだけ読む。
- 制作の共通知識・運用は `docs/knowledge/`。人物・情報・演技は `docs/knowledge/manga/`、読みやすさと共通レビューはknowledge直下の該当文書へ統合し、用途が同じ内容は該当文書へ集約する。参照先と利用Skillの対応は `docs/knowledge/review-workflow.md`。場面監修の知識は `docs/knowledge/supervision/`。必要な観点だけ読み、相談・レビュー時は `.agents/skills/` の該当Skillを使う。重点は `config/review-profiles.json` の1～5とシーン上書きに従う。
- 収録された監修テーマの効果が必要な場面では、字コンテ作成時に `.agents/skills/manga-supervision/SKILL.md` へ表現案を相談し、PNGプレビュー作成後に実際の画像を見て改善案を検討する。テーマは `docs/knowledge/supervision/routing.md` から選ぶ。版0.3.2の追加15テーマは試行版。中心効果と保つ感情をメインが指定して採否を統合する。専用知識のない効果は既存の汎用知識とレビューで扱う。確認事実・制作提案・未確認事項を分け、画像未確認の結果は予備点検とする。
- メインエージェントが制作方針とレビューの採否を統合する。Skillを手順として参照し、必要に応じて対象・目的・重点を渡してサブエージェントへ委任する。
- 映画的演出を動画で試すよう依頼された場合のみ `.agents/skills/manga-video-previsualization/SKILL.md` を使う。通常の漫画制作では動画生成を挟まない。動画の条件・速度・採否も作品側のdocsへ記録する。
- セリフとモノローグは既定で縦書き。採用済みの文字方向指定があれば従う。絵中の短い説明は横書き可。読み順と感情への効果を優先し、意図的な例外は理由を記録する。
- `docs/knowledge/glossary.md` はレビュー時のみ使う。作品用語は `docs/story/TERMS.md` でレビューする。
- フィードバックは「残してほしい」と依頼された場合だけ `docs/feedback/` へ記録する。依頼がなければ記録するかの質問、還元候補の維持、「新規知見なし」の報告は不要。通常の進捗・制作判断・生成条件・検証記録は必要な範囲で残す。手順は `docs/knowledge/feedback-workflow.md`。
- APIキーは作品ごとの `.secrets/` またはローカル環境変数で管理し、docs・共有テンプレート・画像メタデータ・フィードバックに書かない。
- `wait_agent` 使用時は推定残り時間の2倍を範囲内の `timeout_ms` として明示し、不明なら既定時間を明示する。この記載自体はエージェント委任を指示するものではない。

- ノウハウの入口は `docs/MANGA-KNOWHOW.md`。漫画の企画・字コンテ・ネームを主軸にし、映画・ドラマや `screenwriting-skills` は必要箇所だけ参照する。映画コンテを毎回作る工程にはしない。
- PNGの確認対象・回答とPSD作成指示の有無、PSDの仕様・検証・セリフ原文・人間へ残す仕上げは `docs/production/PSD-HANDOFF.md` と `docs/production/DIALOGUE.md` に記録する。PNG確認待ち・PSD作成回答待ちは正規の待機段階とし、依頼済みのPSDは作成・検証・引き渡しまで完了扱いしない。完成の依頼にPSDの自動作成、CBZ作成や外部公開を含めない。
