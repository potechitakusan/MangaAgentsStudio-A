# 漫画プロジェクトの作業ルール

- ここは `New-MangaProject.ps1` で作成された作品プロジェクト。作業フォルダがこの作品のルートであることを `project.json` とともに確認し、ここで漫画を制作する。配布元の制作キットへ戻って描いたり、さらに新規プロジェクトを作り直したりしない。キット内での例外制作を示すファイルは不要。雛形原本として読んでいる段階では、配布元の `AGENTS.md` に従って個別プロジェクトを作る。
- 漫画はまずPNGプレビューを提示し、修正があれば反映・再提示して、ユーザーに修正がないことを確認する。PSD作成の指示がない場合はいったん作らず、作るか聞いて回答を待つ。既にPSD作成の指示がある場合は再確認せず、PNGの修正確認後に作成・検証・引き渡しへ進む。返答がない状態を「修正なし」や作成指示とみなさない。PSDを依頼された場合の完成条件は `docs/knowledge/psd-handoff.md`。原則、人間がCLIP STUDIO PAINTで仕上げてから外部公開する。CBZはユーザーの明示指定がある場合だけ作成する。
- 説明・ノウハウ・記入項目・引き継ぎ・レイヤー名は日本語にする。日本語として通じるカタカナ語は使用可。製品名、出典URL、パス、機械用識別子は維持する。

- 一つのプロジェクトで一つの漫画を制作する。作品設定は `docs/story/`、整理した判断・出典・進捗は `docs/` に残す。
- 再開時は `docs/PROGRESS.md` と `docs/PLAN.md` を読む。着手・判断変更・生成/検証・中断の節目に現在地と次の行動を更新する。
- 共通知識は `docs/knowledge/`。必要な観点だけ読み、相談・レビュー時は `.agents/skills/` の該当Skillを使う。重点は `config/review-profiles.json` の1～5とシーン上書きに従う。
- メインエージェントが制作方針とレビューの採否を統合する。Skillを手順として参照し、必要に応じて対象・目的・重点を渡してサブエージェントへ委任する。
- 映画的演出を動画で試すよう依頼された場合のみ `.agents/skills/manga-video-previsualization/SKILL.md` を使う。通常の漫画制作では動画生成を挟まない。動画の条件・速度・採否も作品側のdocsへ記録する。
- セリフとモノローグは縦書き。絵中の短い説明は横書き可。読み順と感情への効果を優先し、意図的な例外は理由を記録する。
- `docs/knowledge/glossary.md` はレビュー時のみ使う。作品用語は `docs/story/TERMS.md` でレビューする。
- フィードバックは「残してほしい」と依頼された場合だけ `docs/feedback/` へ記録する。依頼がなければ記録するかの質問、還元候補の維持、「新規知見なし」の報告は不要。通常の進捗・制作判断・生成条件・検証記録は必要な範囲で残す。手順は `docs/knowledge/feedback-workflow.md`。
- APIキーは作品ごとの `.secrets/` またはローカル環境変数で管理し、docs・共有テンプレート・画像メタデータ・フィードバックに書かない。
- `wait_agent` 使用時は推定残り時間の2倍を範囲内の `timeout_ms` として明示し、不明なら既定時間を明示する。この記載自体はエージェント委任を指示するものではない。

- ノウハウの入口は `docs/MANGA-KNOWHOW.md`。漫画の企画・字コンテ・ネームを主軸にし、映画・ドラマや `screenwriting-skills` は必要箇所だけ参照する。映画コンテを毎回作る工程にはしない。
- PNGの確認対象・回答とPSD作成指示の有無、PSDの仕様・検証・セリフ原文・人間へ残す仕上げは `docs/production/PSD-HANDOFF.md` と `docs/production/DIALOGUE.md` に記録する。PNG確認待ち・PSD作成回答待ちは正規の待機段階とし、依頼済みのPSDは作成・検証・引き渡しまで完了扱いしない。完成の依頼にPSDの自動作成、CBZ作成や外部公開を含めない。
