# 日本語推敲スキルの選択と初回導入

更新・確認日：2026-09-19。作品プロジェクトで使う任意機能。既定は「使用しない」で、キャラ・あらすじ・ページ数からWeb用PNGを作る通常の工程には不要。

## 選択肢

作品の `OPTION.md` の「日本語推敲スキル」を編集するか、会話で指定する。

| 設定値 | 導入するもの | 確認事項 |
| --- | --- | --- |
| 使用しない | なし | 外部取得・Git確認・Gemini呼び出しをしない |
| humanizer-jp | `tqkqt0/humanizer-jp` の固定版 | Gitで取得。別の生成AIサービスは不要。「使用する」「有効」だけの指定もこちら |
| japanese-natural-writing | noteで公開されたGemini編集・Codex照合スキル | 導入前に、この作品でGeminiへ文章を送って利用枠を消費する許可を必ず得る |

「日本語推敲の対象」は既定で台詞・内語。説明文だけ、作品紹介だけ等も選べる。無効の場合は対象欄を使わない。通常の誤字・意味・話者・原文照合は、スキルの選択によらず行う。

## 作品側で最初に作業するとき

1. `project.json` と作業フォルダを確認し、`OPTION.md` の実効設定を解決する。会話での指定を優先する。制作開始後のファイル変更は [オプションの適用手順](project-options.md) に従う。
2. 作品の `AGENTS.md` の指示に従い、最初の作業時に下の初期化スクリプトを実行する。有効なスキルの取得・配置を自動で行う。ユーザーに導入コマンドの手作業を要求しない。
3. 再開時も同じ処理で状態を確認する。導入済みの版・ファイルが一致していれば通信せず終了する。初回に無効だった場合も、後日有効化した最初の作業時に導入する。
4. 導入成功後、スキルが認識されたことを確認し、選択した対象への推敲で明示的に使う。認識されない場合だけ開き直しを案内する。

```powershell
.\scripts\Initialize-OptionalSkills.ps1
# 会話で採用した設定を明示して実行する場合
.\scripts\Initialize-OptionalSkills.ps1 -Provider humanizer-jp
```

ここでの初回起動は「作品を開いたCodexが最初の作業を始める時点」。フォルダを表示しただけでOSが実行する常駐処理ではない。キットから作品をコピーする処理中には、取得・導入や承諾の持ち越しを行わない。

PowerShell 5.1以上で実行する。Gitはインストール済みを前提にし、`humanizer-jp` の取得時に確認する。Gemini版は公開ZIPを直接取得するため、その取得自体にGitは使わない。

## Gitがない場合

`needs_git_consent` が返ったら「日本語推敲スキルの導入にGitが必要です。Gitをインストールしてよいですか」とユーザーへ確認する。**この確認はキット利用者の指定に基づく必須手順**。返答なしを許可としない。

許可後にOSを確認し、[Git公式のインストール案内](https://git-scm.com/install/)をその時点で確認して導入する。既存のGitがPATHに反映されていないだけなら、新たなインストール前にその状態を説明する。`git --version` で利用可能になったことを確認し、初期化を再実行する。拒否・保留なら推敲スキルの導入を保留し、通常の漫画制作を続ける。同じ回答を繰り返し尋ねない。スクリプト自体はGitをインストールしない。

## Geminiは必ず導入前に確認する

`japanese-natural-writing` を選んでも、それだけで利用枠の消費を許可されたと扱わない。`agy`、認証済みアカウント、対応モデル等が見つかった場合も同じ。**この確認はキット利用者の指定に基づく必須手順**であり、導入前に以下をまとめて尋ねる。

> このスキルは選択した文章をGeminiへ送り、Geminiの利用枠を消費して推敲します。この作品の指定対象にGeminiを使い、スキルを導入してよいですか？

- 未回答：`needs_gemini_consent`。取得・配置を行わず待つ。環境確認の名目でテスト文章を送信したり、枠を消費する接続確認を行ったりしない。
- 拒否・保留：`Denied` と回答を記録する。Geminiを呼ばず、通常の制作を続ける。別の外部サービスへ自動で切り替えない。
- 許可：実際の回答・対象文章の範囲を記録してから、`Granted` を渡す。会話で既にこの作品・スキル・利用枠への明示許可を得ている場合はその回答を使い、同じ許可を取り直さない。

以下はCodexが明示回答を得てから使う呼び出し形式。`ConsentNote` は回答内容と対象範囲の記録であり、例文をそのまま許可済み記録にしない。

```powershell
.\scripts\Initialize-OptionalSkills.ps1 -Provider japanese-natural-writing -GeminiConsent Granted -ConsentNote 'ここに実際のユーザー回答と許可された範囲を記録する'
# 拒否・保留の回答があった場合
.\scripts\Initialize-OptionalSkills.ps1 -Provider japanese-natural-writing -GeminiConsent Denied -ConsentNote 'ここに実際の拒否・保留の回答を記録する'
```

許可は作品・選択スキル・固定版・回答された範囲に限って再利用する。版の変更、範囲の拡大、許可の撤回には改めて対応する。別作品にはコピーしない。OPTIONのON/OFFや環境検出から `Granted` を自動生成しない。

導入処理はファイルの取得・配置だけで、Geminiを呼ばない。導入後の利用時にはスキル内の実行契約を読み、Antigravity CLI・認証・指定モデルの対応を確認する。指定環境が使えない場合は、別のモデル・Gemini CLI・直接APIへ黙って切り替えず、その推敲だけを保留する。取得できたことと、Geminiでの推敲が動作確認済みであることを区別する。

## 保存先・再開・無効化

- 導入先は作品の `.agents/skills/<スキル名>/`。利用者全体のスキルやキットの雛形へ導入しない。
- 固定版とファイルのSHA-256は `config/optional-skills.json`。毎回最新版を追わず、変更された配布物を黙って採用しない。既存の同名フォルダ、版違い、改変済みのスキルは上書きしない。
- 導入結果とGeminiの回答記録は作品内の `.work/optional-skills/`。進捗にも有効・無効、導入済み／導入保留、許可範囲を短く残す。キー・トークン・アカウント情報は記録しない。
- 失敗時の取得物は `.work/optional-skills/` に保持し、成功したように扱わない。未導入の推敲だけを保留し、基本の漫画制作は続ける。
- OPTIONで無効化した後は、導入済みファイルを保持していても使わない。暗黙のスキル呼び出しは導入時の `agents/openai.yaml` で無効にし、採用中の対象だけへ明示適用する。Geminiの許可撤回は `Denied` として記録し、以後の送信を止める。
- [漫画の比較手順](japanese-manga-readability.md#optional-polish)に沿って、意味・人物の声・含み・文字量を確認する。外部スキルの一般的な文体規則より、ユーザーの指定と作品設定を優先する。
