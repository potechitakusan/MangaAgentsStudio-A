# 外部画像生成でコマ別に作画する共通手順

整理日：2026-09-26。Qwenでの制作記録から採用した判断手順。複数モデルで効果を実証した手順ではない。根拠と試行数は [制作根拠の要約](image-generation/production-evidence.md)、固有の症状・操作は [Qwen-Image 2.1](image-generation/qwen-image-2.1.md) に分ける。

## 対象と入口

下絵・撮影・参照画像を条件にコマ原画を作り、ページへ組み立てる場合に使う。入口は `manga-ai-production`、この方式を選んだ後の手順は `manga-external-panel-i2i`。文字だけから作るt2i、接続確認だけの依頼、imagegenによる新規のコマ・ページ作画は対象外。imagegenのページ作画は [コマ割り運用方針](panel-layout-policy.md) に従う。

ここでのi2iは「画像を条件に作画する」という広い呼称であり、次の機能を同一視しない。

| 入力方式 | 実行前に確かめること |
| --- | --- |
| 初期画像を変形する | 初期画像・マスク・強度の意味、生成寸法との関係 |
| 複数画像の内容を参照する | 対応枚数、接続先、画像番号・投入順と指示の対応 |
| 制御画像で構造を指定する | 対応モデル・制御機能・前処理・強度 |
| 外見・画風の専用参照を使う | 参照対象、他機能との併用、枚数・追加費用 |

モデル名・版と実行環境を分けて確認し、対応しない機能をあるものとして扱わない。入力方式・枚数・費用の確認は各サービスの資料に従う。NovelAIは [API手順](novelai-api.md) と [Opusの条件](ai-production.md#novelai-opus) を参照する。実験の登録やこの手順の選択だけでは有料利用の許可にならない。

初期参照や完成前編集にimagegenを併用するか、BlenderやLoRAを使うかは作品の採用方針による。特定作品の「imagegenは初期参照と完成前編集だけ」という制限を全作品へ広げない。採用した作品では、新規の場面作画を参照・完成前編集と呼び替えて制限を回避しない。

<a id="c1"></a>

## C1：作画へ渡すコマの意図

注目対象、見える人数、人物と小物の位置、動作の前後、画角、顔の見せ方、残す接点を整理する。画角と距離は [画角・視点](manga/02-visual-direction.md)、無言の間や情報量は [変化・緩急・提示順](manga/03-beat-pacing-timing.md) を使い、生成側は決まった意図を画像入力・文章へ変換する。角度の種類や顔を隠すコマの数を増やすこと自体を目的にしない。

比較時は同じコマと基本条件を使い、変更点を列挙する。別シナリオの改善や複数条件を同時に変えた結果から、特定パラメーターの効果や一般的成功率を求めない。

<a id="c2"></a>

## C2：画像に担わせる情報を分ける

| 資料 | 主に担わせる情報 | 別の資料・指示で決める情報 |
| --- | --- | --- |
| 下絵・Blender撮影等 | 画角、人物位置、動作、前後関係、接点 | 最終の顔・手・服・背景の描写 |
| キャラ参照 | 顔、髪型、衣装、配色、識別要素 | そのコマの姿勢、視線、感情 |
| 小物参照 | 形、模様、配色、材質 | 画面内の寸法、向き、置き場所、接触 |

これは制作側の役割分担で、生成機能が自動的に分離する保証ではない。画像番号・投入順・強度・マスクへの変換はモデル別に行い、複数画像を受け付けない機能へ同じ構成を要求しない。

そのコマに必要な参照を選び、実際に接続・添付した画像を記録する。パスをプロンプトへ書くだけで画像入力済みとはしない。局所修正では完成原画の情報で足りるかを判断し、不要な参照を減らす案も比較する。有効性はモデルごとに確認する。

<a id="c3"></a>

## C3：構図資料と切り抜きの余地

Blenderを使う場合は必要な人物・物体を置き、視線・手元・接点・遮蔽を撮影前に確認する。シーン内に存在する人数と、撮影画像に見える人数を分ける。粗いモデルの顔や輪郭をどこまで描き直すかも伝える。不要な人物や顔の断片が生成へ影響するかはモデル別の観察として扱う。

後で切り抜く場合は手足・道具の先端や吹き出しの場所を残す。一方、広く撮るほど被写体の画素数が減るため、余白と必要な細部の両方で判断する。50mm・85mm・切り抜き75%等を全作品の定数にしない。Blender以外の下絵でも同じ確認項目を使える。

<a id="c4"></a>

## C4：試作、修正、採否

代表的な難所で、構図、人物数、外見、手と小物の接触、顔を見せない指示が保たれるか実画像を確認する。全コマへ展開する前に、その生成環境で使える入力方式を確かめる。

不一致は構図資料、不要な参照、文章、モデル固有設定、完成画像の局所編集、切り抜きのどこで直すか判断する。画角・動作全体の違いを顔だけの修正で採用済みにしない。同じ指示の反復で改善するとは仮定しない。再試行の回数・費用・失敗時の扱いはサービスの運用と今回の許可範囲に従い、改善しない場合や上限に達した場合は条件を見直す。結果・消費不明の要求は自動再送しない。

<a id="c5"></a>

## C5：切り抜きとページでの確認

[ページ設定](page-layout.md)に従い、コマの生成希望寸法、取得実寸、採用する切り抜き、組立先のページ寸法を幅×高さで分ける。１コマの実寸をページ全体の実寸として扱わない。固定比率で自動的に切らず、顔・手・動作の端・余白と掲載時に必要な画素数を確認する。imagegen以外では文字・吹き出しを作画後に別に載せる。原画に意図しない文字・吹き出しがないか確認し、枠も別に作る構成では枠の混入を点検する。

仕上げモデルやLoRAを通した場合も、人物の左右、衣装、表情、道具、隠した顔を再確認する。単独コマがきれいでも、ページで物の受け渡し・視線・動作の前後がつながらなければ修正する。構図の改善と描写品質の改善は分けて採否を判断する。

文字組版は [読みやすさ](japanese-manga-readability.md)、通読と修正は [制作工程](manga/08-workflow-review.md)、PNGの修正確認と指示のあるPSDは [引き渡し](psd-handoff.md) へ戻る。肯定的な感想だけで「修正なし」やPSD作成指示を補わない。

<a id="c6"></a>

## C6：再利用できる記録

作品の通常の制作記録・実験記録に、次を必要な範囲で残す。新しい必須記入票を制作開始条件にはしない。

- サービス、モデル名・版、ノード等の実行環境、取得可能な識別情報・設定。
- コマの意図、実入力画像と接続順、実送信文、生成希望寸法と取得実寸。
- 採用原画、変更点、不採用と失敗、再試行ごとの条件、切り抜き範囲、後処理。
- 状態（未試行・観察・条件付きで再現・共通化候補・棄却）、根拠の日付、適用条件、反例、未確認事項。

予定した参照の存在と実投入を区別し、秘密情報は含めない。実画像を新たに見ていない整理では過去の実画像レビューを出典にし、今回再検証したとは書かない。作品固有の素材や個人設定は共通雛形へ持ち込まない。

他モデルでも確認した処方は、入力方式・対象・限界を示して共通化を検討する。同じ基盤モデルの別ノードだけを独立したモデル間検証には数えない。フィードバックの追加記録・キットへの還元は [依頼がある場合の手順](feedback-workflow.md) に従う。
