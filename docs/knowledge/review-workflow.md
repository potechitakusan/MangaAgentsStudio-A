# レビューの重点設定と役割分担

更新: 2026-09-17。以下は本プロジェクトの運用設計であり、評価効果を実証した尺度ではない。

## 1～5の意味

重点は「その観点の品質点」ではなく、レビューで割く注意と修正優先度。1=軽い確認、2=必要箇所、3=標準、4=詳しく、5=中心課題として複数案を比較する。1でも読み順破綻や設定矛盾を見逃してよい意味にはしない。

| キー | 観点 | 初期重点 |
| --- | --- | --- |
| immersion | 世界への没入、感情、間、情報密度 | 5 |
| cinema | 画角、視点、空間、カットの接続 | 4 |
| story | 欲求、障害、因果、変化、結末 | 4 |
| readability | 日本語、フキダシ、コマ順、視線誘導 | 5 |
| characterConsistency | 顔、髪、衣装、小物、体格の継続性 | 4 |
| terminology | 設定用語と制作指示の呼称 | 3 |

設定は `config/review-profiles.json`。解決順は defaults → シーンのpreset（なければコマンドのPreset）→ シーンのweights。指定シーンが存在しない場合は誤記とみなしエラー。Preset省略時はbase相当。プリセットは漫画ジャンルを決めつけるものではなく初期候補とする。

```powershell
.\scripts\Resolve-ReviewProfile.ps1 -ConfigPath '.\config\review-profiles.json' -Preset 'confession'
.\scripts\Resolve-ReviewProfile.ps1 -ConfigPath '.\config\review-profiles.json' -SceneId 'scene-001'
```

シーン設定例（scenesの中へ追加）:

```json
"scene-001": {
  "preset": "confession",
  "weights": { "cinema": 5, "terminology": 2 },
  "reason": "言えない気持ちを手と距離で見せる"
}
```

## 共通知識の参照先

ジャンル共通の知識は、用途とレビュー観点に沿って以下の既存文書にまとめる。同じ用途の追記は該当項目へ統合し、用途ごとに集約する。各Skillは担当する観点に必要な箇所だけを読む。

| 用途 | 本文 | 主に使うSkill |
| --- | --- | --- |
| 人物の欲求・変化・因果・回収・終幕 | [物語・人物・テーマ](manga/05-story-character.md) | `manga-story-review` |
| 演技・台詞・場面の変化 | [場面・台詞・小道具](manga/04-scene-dialogue-props.md) | `manga-story-review`、`manga-immersion-review`、`manga-cinema-review` |
| 情報差・前振り・緩急・無言 | [変化・緩急・提示順](manga/03-beat-pacing-timing.md) | `manga-immersion-review` |
| 注目対象・反応・身体・空間 | [画角・視点](manga/02-visual-direction.md) | `manga-cinema-review` |
| 絵と台詞の伝達・読み順・表示条件 | [日本語漫画の読みやすさ](japanese-manga-readability.md) | `manga-readability-review` |
| 指摘・比較・実画像と読者反応の確認 | この文書の[レビュー記録](#レビュー記録)以降 | 各レビュースキルと `manga-supervision` |

`manga/` は漫画の工程・技法の索引、knowledge直下の各文書は読みやすさ等の観点別詳細と運用手順を担う。PSD引き渡し・制作設定・Codex操作・任意の動画試作は、各作業の目的に応じて参照する。ギャグ専用の表現案と監修は [supervision/gag/](supervision/gag/README.md) で扱い、人物・因果・読順の共通判断には上の本文を使う。

## 制作と相談の流れ

メインエージェントが作品の狙いとシーンの「前→後の変化」を把握し、字コンテ/ネームを作る。必要な観点のSkillに相談して案を比較し、レビュー指摘を統合する。Skillを呼ぶだけで別エージェントが起動するわけではない。委任可能な環境では、目的・対象ページ・実効重点・該当Skillのパスをサブエージェントに渡す。

| Skill | 主に見る対象 | 通常の使用場面 |
| --- | --- | --- |
| manga-immersion-review | 感情、間、説明過多 | 字コンテ・ネームの読後感レビュー |
| manga-cinema-review | 距離、方向、ショット接続 | シーンのカット設計への相談・レビュー |
| manga-story-review | 役割、欲求、因果、変化 | あらすじ・1話・シーンの構成相談 |
| manga-supervision | 笑いを狙う場面のギャグ表現（専用監修はギャグのみ） | 字コンテで表現案を相談し、プレビューを見て改善案を検討 |
| manga-readability-review | 縦書き、読み順、文字配置 | ネーム・文字入れの相談とレビュー |
| manga-ai-production | キャラ一貫性、モデル選択、実験 | 参照絵からコマを制作する段階 |
| manga-terminology-review | 用語と設定の表記ゆれ | レビュー時のみ。初稿執筆には辞書を読ませない |

レビュー依頼は「scene-003、p4～5、告白直前の緊張を残したい。無言コマの要否と画角を検討。本文は…」のように対象と効果を指定する。制作中に全Skillを毎回呼ぶ必要はない。

### ギャグ監修を使う二つの段階

笑いを狙う場面では、字コンテ作成時にメインから `manga-supervision` へ、場面の狙い・要素・残したい効果を渡して表現案を得る。PNGプレビュー作成後は、対象画像を実際に開いて同じ狙いが伝わるかを点検し、改善案を返す。[監修の進め方](supervision/routing.md)に従い、主効果を保ってギャグの案を比較する。専用監修はギャグのみ。別エージェントの起動は必須ではない。

確認事実、制作提案、未確認事項を分ける。汎用的な判断は [共通知識](review-workflow.md#common-knowledge) を参照する。記録は [監修相談・レビュー](../reviews/SUPERVISION.md) を使い、メインが採否を統合する。ジャンル用の重みや品質点は追加せず、既存の観点へ関係する指摘を戻す。画像未確認の判断は文章上の予備点検とする。

## レビュー記録

`docs/reviews/` に次を残す。

| 対象 | 観点/重点 | 観察した事実 | 読者への影響の仮説 | 重大度1～3 | 改善案 | 失う効果/残す例外 |
| --- | --- | --- | --- | --- | --- | --- |

重大度は1=軽微、2=理解や感情を阻害、3=読む順や物語が成立しない。修正順の補助値は重点×重大度だが、読めない/設定破綻は先に解消する。数値だけで機械的に合否判定しない。指摘のない観点は「確認済み」とするか対象外理由を残し、無理に問題を作らない。

対象の版と箇所、観察した事実、読者への影響の仮説、改善案、保つ効果／失う効果を結び付ける。「テンポが悪い」だけで済ませず、重複説明、人物の目的不足、認識の飛躍、必要な証拠の不足、反応の重複へ切り分ける。

PNG等の画像レビューは対象画像を実際に開いて行う。字コンテから完成画像の表情や読み順を確認済みにしない。画像が見られない場合は文章上の予備点検として続け、視覚上の判断は未確認にする。修正後は変更箇所と必要な前後だけを再確認する。

メインエージェントは指摘ごとの採否と理由を記録する。修正後は影響するページと前後接続を確認する。

作品の通常の制作判断・修正・検証記録は必要な範囲で残す。個別作品のフィードバックをキットへ還元する記録は、ユーザーが依頼した場合だけ行う。監修したこと自体を、素材や台詞を共通知識へ移す許可としない。依頼がなければ記録するかの確認はしない。

## 比較案の作り方

残す情報や場面の目的をそろえ、知りたい差を変える。説明の有無、無言の反応、聞き手、証拠の出し方などを比較する。同じ結末を知った読者の２回目の反応を、初見の驚きの比較に使わない。

途中で読むのを止めて予想を聞く試験は、通常の通読とは条件が違う。提示順、事前知識、表示方式、作者の補足を記録する。少数の反応をジャンル全般の標準値にしない。

## 分けて確認すること

- 理解：何が起き、誰が何を望み、なぜ結果につながったと読んだか。
- 予測：どこで何を予想し、何で解釈が変わったか。
- 感情と好み：面白さ、怖さ、共感、人物への印象がどうだったか。
- 読みやすさ：どこへ戻ったか、主語・対象・言葉・因果のどれが分からなかったか。

自由回答を先に聞く。エージェントの推測を実読者の反応と書かず、未実施の試読を補わない。理解できたことと、狙った感情が生じたことを分ける。

## ジャンルを併用した修正を確かめる

笑いの追加が人物の真剣な願いを消した、逆転が既出の制約を消した、関係の決着を別の能力だけで決めた等、修正が守るべき前提を変えていないかを見る。主効果と今回変えた一箇所を結び付け、採用案の確認へ戻す。

知識の配布・参照先が正しいことと、その知識で漫画が面白くなったことは別。形式検証、字コンテ上の相談、実画像のレビュー、実読者の反応を区別して記録する。

## 漫画の制作と引き渡し

収録内容は作品の `docs/MANGA-KNOWHOW.md` から選ぶ。[ネームからPSDまで](manga/08-workflow-review.md)に従い、漫画の企画・字コンテ・ネームを主軸に、必要な場面の複数案、通読、レビューの統合改稿を行う。映画・ドラマや脚本スキルは必要箇所の補助参照とする。

まずPNGプレビューで確認・修正し、ユーザーに修正がないことを確認する。PSD作成の指示がなければ作るか聞いて回答を待ち、既に指示があれば再確認しない。依頼されたPSDは[作成・検証・引き渡し](psd-handoff.md)まで行う。PNG確認待ち・PSD作成回答待ちは正規の待機段階とする。原則、人間がCLIP STUDIO PAINTで仕上げてから外部公開する。CBZは明示指定時だけ作成する。画像制作スキルはこの確認手順を含めて参照し、各レビュースキルは依頼された観点の検証を担う。
