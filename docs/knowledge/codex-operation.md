## 作品フォルダでCodexを開き直す

**キットの運用ルール:** 配布元は保守・配布用とし、通常の漫画制作は `scripts/New-MangaProject.ps1` でキット外に作った個別プロジェクトで行う。作成に成功し、作品の `project.json` と `AGENTS.md` が存在することを確認してから、Codexはユーザーへ次の内容を案内する。`-WhatIf` や途中失敗を作成完了として扱わない。

1. 作成した作品プロジェクトの絶対パスを、省略せずコピーできる形で示す。実行結果の `AbsolutePath` または実在する作成先から解決したパスを使い、フォルダ名やパスを推測で補わない。
2. 「このフォルダでCodexを開き直してください。作品フォルダで新しい会話を始めてから漫画を制作します」と伝える。
3. 「やり方がわからない場合は、ご利用の環境（Windows／Mac、アプリ／VS Code）を教えてください。必要な手順をご案内します」と添える。作成のたびに操作手順を検索・説明したり、全員に手順の要否への回答を求めたりしない。手順がわかるユーザーは返信せず作品フォルダを開いてよい。返答がないことを、開き直し完了や手順説明の依頼とは扱わない。
4. 開いた先で `AGENTS.md`、`project.json`、`docs/PLAN.md`、`docs/PROGRESS.md` を確認し、`docs/story/BRIEF.md` から制作を始めるよう伝える。既存作品なら進捗を読んで再開する。

絶対パスはユーザーへの開き直し案内に表示する。配布文書・設定・保存記録には相対パスを使い、実機の絶対パスを雛形へ書き込まない。現在の会話で作成先へ移動しただけでは、Codexのプロジェクトや読み込む指示が切り替わったと扱わない。

### 手順を求められた場合だけ最新の公式情報を調べる

**Codexへの指示:** ユーザーが開き方を質問した場合や、やり方がわからないと伝えた場合に、利用環境に合う操作手順を案内する。環境が不明な場合だけOSとアプリ／VS Codeのどちらを使うか確認し、会話で判明している情報は聞き直さない。既に手順を求められていれば説明の要否は再確認しない。

詳細を説明するときは、以下の手順例を固定の最新情報として再利用せず、その時点の公式情報を検索し、該当ページの本文を実際に読む。利用可能ならOpenAI Docsの手順を使う。公式ページが移転していたら公式サイト内で探し直す。開く対象は、作成済みで実在を確認した作品フォルダにする。

- ChatGPTのWindows用・Mac用アプリを使う場合: 利用するOSについて、インストール・サインイン、Codexの選択、ローカルフォルダの追加・選択、新しい会話の開始までを調べる。
- VS Codeを使う場合: 公式Codex拡張機能の導入、作品フォルダの選択、Codexの起動・サインイン、新しい会話の開始までを調べる。
- 複数の環境での説明を求められた場合は、その範囲を調べる。毎回すべてのOS・アプリの手順を揃える必要はない。
- 案内の本文に閲覧した公式ページへのリンクと確認日を添える。確認できた操作と未確認の画面表示を区別する。検索できない場合は「最新情報は未確認」と伝え、確認日付きの参考情報だけを示す。確認できないボタン名や対応状況を作らない。

### ChatGPTのWindows用・Mac用アプリで開く手順例

**公式情報で確認した内容（2026-09-13）:** 両OSともChatGPTデスクトップアプリでサインインし、ChatGPTのドロップダウンからCodexを選べる。インストールと選択の出典は[デスクトップアプリ](https://learn.chatgpt.com/docs/app)と[Quickstart](https://learn.chatgpt.com/docs/quickstart)。

1. 利用しているOS用のChatGPTアプリを開き、サインインする。未導入なら公式の案内からインストールする。
2. ChatGPTのドロップダウンからCodexを選ぶ。
3. 作成した作品フォルダをローカルプロジェクトとして開く・追加する。フォルダを設定する場合はプロジェクトのメニューから `Edit project` → `Add folder` を使い、案内された絶対パスの作品フォルダを選ぶ。複数フォルダがある場合は作品フォルダを `Make primary` で主フォルダにする。
4. その作品プロジェクトを選んで `New chat` を開き、制作を依頼する。

ローカルプロジェクトへのフォルダ追加と主フォルダ設定は[Projects and chats](https://learn.chatgpt.com/docs/projects)に基づく。主フォルダは新しい会話の作業場所と、Codexが `AGENTS.md` やスキルを自動検出する基準になる。上の手順を作品フォルダに適用することは、このキットの運用上の指定。実際のWindows・Macの画面での操作は未検証で、案内時には最新公式情報との一致を確認する。

### VS Codeで開く手順例

**公式情報で確認した内容（2026-09-13）:** VS CodeではCodex拡張機能を使い、開いているフォルダまたはワークスペースがローカルプロジェクトになる。[Codex IDE extension](https://learn.chatgpt.com/docs/codex/ide)、[Projects and chats](https://learn.chatgpt.com/docs/projects)。

1. VS Codeで作成先の作品フォルダを開く。フォルダを選ぶ際は、案内された絶対パスと一致することを確かめる。
2. 未導入ならOpenAI公式の案内からCodex拡張機能をインストールし、サインインする。
3. Codexアイコンを選ぶ。表示されない場合はコマンドパレットから `Codex: Open Codex Sidebar` を実行する。
4. 作品フォルダを対象に新しい会話を始める。複数ルートのワークスペースなら、この作品のルートを会話の対象に選ぶ。

拡張機能の導入と起動コマンドは[Codex IDE extension](https://learn.chatgpt.com/docs/codex/ide)、ワークスペースの選択は[Projects and chats](https://learn.chatgpt.com/docs/projects)に基づく。実際のVS Code画面での操作は未検証。ボタン名・コマンド・サインイン方法は案内時点で調べ直す。

## スキルと指示ファイル

公式文書では、Skillsのnameとdescriptionを候補選択に使い、必要時に本文を読む。リポジトリのローカルSkillsは `.agents/skills/` に配置できる。[Build skills](https://learn.chatgpt.com/docs/build-skills)

AGENTS.mdはプロジェクトの指示を置く場所で、親子の適用範囲やoverrideがある。作品ルートから開始し、意図した指示が認識されているか確認する。[AGENTS.md公式文書](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

スキル設計の参考資料として次の記事を参照した。具体的な発火条件、必要な資料だけを読む構成、常時指示の肥大化を避ける方針を、スキルの設計に採用する。[Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)

## このプロジェクトの選択

- 安定した約束はAGENTS.md、詳細な知識はdocs、特定場面の相談・レビュー手順はSkill、今回の制作目的は依頼文へ置く。
- Skillsは独立実行プロセスではない。メインエージェントが手順を使うか、利用可能なサブエージェントに対象と手順を渡す。
- 進捗ファイルは実行中の処理を保存する機能ではない。セッションが切れたら、記録した出力と実行IDを確認してから再開し、生成依頼を無条件で重複送信しない。
- 再開に必要な記録は現在の目的、完了ファイル、進行中処理、決定事項、未確定事項、直後の行動。外部サービスの秘密値は記載しない。
- モデル名や利用可能ツールをSkill内で固定しない。環境で使えるものを確認し、モデルの能力や価格を推測で書かない。

この文書は作品へ配布する。個別の指示原文と開発中の調査ログは配布しない。
