# 依頼がある場合のフィードバック記録

更新：2026-09-13。作品テンプレートで作成したプロジェクトに適用する制作運用。

## 記録を始める条件

ユーザーから「フィードバックを残してほしい」など、記録する依頼があった場合だけ、`docs/feedback/` に知見を整理する。記録してよいか、記録するかを確認する必要はない。依頼がなければ、フィードバックの新規記録・候補の維持・「新規知見なし」という報告は行わない。継続的な記録を依頼された場合は、その対象と期間に従う。

進捗、修正の採否、PNGの確認、PSDの検証、生成の再開に必要な条件は通常の制作記録であり、必要な範囲で残す。これらをフィードバックの別名として増やさない。

## 依頼されたときの記録項目

`docs/feedback/TEMPLATE.md` を使い、依頼された範囲だけ記録する。

- 課題、試した変更、固定した条件、比較対象。
- 入出力の相対パス、モデル・ワークフローの識別情報と主要設定。
- 観察結果、試行数、失敗、適用できる条件と反例。
- 状態：未試行、観察、条件付きで再現、共通化候補、棄却。
- 共通知識へ提案する最小の変更と、その根拠。

読者評価をしていない提案を実証済みと扱わない。個別作品の好みを一般法則にせず、認証情報・未公開素材・未整理ログを含めない。

## 共通知識へ取り込む場合

記録の作成と外部への送信は別の作業。共有・取り込みを依頼された範囲で、根拠と再現条件を確認し、採用・保留・棄却を判断する。作品一式をコピーせず、必要な知見だけを反映する。既存作品を自動更新しない。
