# 漫画の演出を短い動画で試す

更新: 2026-09-12。適用範囲: ユーザーが映画的な演出を動画で試したいと依頼した場合の任意工程。通常の漫画制作は動画生成を経由しない。

本文は本プロジェクトの**制作上の運用案**であり、特定モデルの性能保証ではない。モデルの正式名称、対応入力、尺・音声仕様、プロンプトの外部根拠・確認日は [動画モデルとプロンプトの調査](video-prompting.md) を参照する。実機での成功・失敗・速度は各作品の `docs/experiments/` に記録し、資料を読んだことと生成を確認したことを分ける。

## 動画を作る目的

画角、空間のつながり、行動と反応、緊張から解放までの間が伝わるかを映像で観察する。動画で成立した動きも、漫画では省略、コマの同時視認、ページめくり、読者の読む速度を踏まえて再設計する。一カットを一コマへ機械的に置き換えない。漫画への適用は [没入と映画的演出](immersion-and-cinema.md) と併せて判断する。

## 最初に用意するもの

| 対象 | 決める内容 | 作品内の配置 |
| --- | --- | --- |
| 試作の狙い | 確認したい効果、約何秒か、誰に何が伝われば採用できるか | docs/experiments/ |
| 人物参照 | 内蔵画像生成で作った基準画像、固定特徴、衣装、左右の目印、版/ハッシュ | assets/characters/ |
| 空間とカット | 人物位置、画面内の移動方向、開始/終了状態、主要動作、カメラ | docs/experiments/ |
| 日本語台詞 | 話者、本文、話し始め、時間枠、話し方 | docs/experiments/ |
| 実行環境 | 利用するComfyUI、GPU、実際のモデル/ノード版、保存先 | docs/experiments/ |
| ワークフロー | 動作確認済み原本を確認した上で作った作業用コピー | workflows/ |
| 生成物 | カット、音声、連結版、比較用の静止画 | output/ |

人物は同じシートに複数人を置くと誰を参照するか曖昧になる可能性がある。単独の基準画像で顔・髪・衣装・体格を確認し、複数人のカットでは立ち位置と各人物を明記する。この方針は試作上の提案であり、モデルによる参照能力の差を確認する。必要な始端画像や中間画像も採用済みの基準に戻って作り、生成を重ねた外見のずれを検出する。

## ワークフローを確かめる

MiniMax H3の動作確認済みワークフローを起点に、JSONのノードと実際に参照するモデルを読む。H3のモデル種別、量子化、短縮用LoRAの違いは [モデル調査](video-prompting.md) で確認する。短い呼称やファイル名だけで互換性を決めず、原本の提供者による動作確認と、現在の入力を使う今回の動作確認を別々に記録する。

実行前に、参照画像をどの入力へ渡すか、生成尺とフレーム数の制約、FPS、解像度、出力保存、音声対応を確認する。GUI用JSONと実行API用JSONの形式差にも注意し、使用環境にある変換・投入手段で検証する。最初は予定カットの一つを基準として実行し、全カットを一度に投入する前に入出力が結び付くことを確認する。

元の動作確認済みファイルは保持する。作品内のコピーで設定を変え、何を変えたか記録する。認証情報や他作品の絶対パスを共有用ファイルへ含めない。利用可能なモデルが不足している場合は、必要なファイルの正式名・出典URL・置き場所・目的を整理してユーザーへダウンロードを依頼する。

## カットを組み立てる

**制作上の目安:** 約20秒なら4～7秒のカットを複数用意する。同梱の補助処理では各素材を10秒以下に保ち、モデルが受け付ける尺/FPS/フレーム数に合わせる。プロンプトに多数の連続動作を詰め込む前に、ひとつの因果関係を読み取れる単位へ分割する。

| カット計画の項目 | 記録すること |
| --- | --- |
| カットIDと時間 | 目標尺、連結後の開始時刻、使用する参照 |
| 開始状態 | 登場人物の位置、姿勢、表情、視線 |
| 主要動作 | 誰が何をして、相手や周囲がどう反応するか |
| 終了状態 | 次カットへ渡す姿勢、位置、感情、移動方向 |
| カメラ | 画角、見る方向、必要な移動。演技と競合する複雑な動きは試作で評価 |
| 台詞と音 | 話者、日本語本文、時間枠、必要な環境音 |

例えば「交渉が決裂 → 襲撃開始 → 一人目を回避して制する → 二人目を制して余裕を見せる」と分けられる。人物が複数いても、観察者が誰の行動を追うか分かる構図を選ぶ。これは初期の演出候補であり、要求された動作が実際に出力されたかは生成後に判定する。

隣接カットでは、衣装・顔・人数・立ち位置・画面内の左右・倒れた人物の状態を比較する。連結前の動画の形式、解像度、FPS、音声構成を調べ、必要に応じて揃える。完成版の実尺を測り、フレーム数による端数や音声の切れがないか確認する。

## 日本語音声と確認

モデルの音声機能が日本語台詞に対応するかは実行時の版で確認する。音声のない動画は、利用できる別の音声生成手段で台詞を作り、話者・声・速度・発話位置を記録して合成する。後付けの台詞なら、口元が大きく映るカットの同期、あるいは声を画面外に置く演出を検討する。台詞が映像の時間枠を超える場合は、聞き取れる速度を保ちながら文章やカット尺を調整する。

映像は始端/中間/終端と動作の要所を見て、可能なら通常速度でも確認する。音声は実際に試聴し、日本語の発音、話者との対応、音量差、無音、途中切れを確かめる。メディア情報の解析や文字起こしは補助であり、試聴の実施を証明しない。試聴できない環境なら音声確認を未実施として残す。字幕は補助表示であり、日本語音声の代わりとして完成扱いしない。

## 客観的に比べるための記録

採点の基準を生成前に定める。以下はこの用途の暫定例であり、作品ごとの狙いに合わせて変える。

| 評価軸 | 観察する点 | 暫定判定 |
| --- | --- | --- |
| 動作の読み取り | 回避→相手の反応など、指定した因果が映像にあるか | 0=伝わらない、1=曖昧、2=明確 |
| 人物の同一性 | 顔・髪・衣装・体格・人数の変化 | 0=別人/混合、1=修正が必要、2=保持 |
| 空間と接続 | 左右・移動方向・位置・前後の状態 | 0=矛盾、1=説明不足、2=連続 |
| 身体と接触 | 手足の数、形、接触、物のすり抜け | 0=重大破綻、1=軽微、2=狙いを妨げない |
| 演技 | 余裕、怒り、緊張等の狙いが読めるか | 0=逆/無表情、1=曖昧、2=明確 |
| 音声 | 日本語台詞、話者、聞き取り、同期 | 0=欠落/不成立、1=修正が必要、2=成立、未試聴は未確認 |

各カットと連結版の採否、評価者、試行数、採用数、失敗理由を残す。自分で決めた暫定点数を読者の実測評価と呼ばない。「成功1件」から一般的な成功率を断定せず、再現できた条件と未確認の条件を分ける。

生成条件には、参照画像のID/版/ハッシュ、全文プロンプト、ネガティブ指定があればその全文、workflowの版/ハッシュ、モデルとノードの版、seed、sampler等の主要設定、精度、解像度、FPS、フレーム数、実尺を記録する。速度は初回ロード、推論、保存/後処理、連結/音声処理を可能な範囲で分け、秒/カットと生成秒/映像1秒を残す。ジョブID、送信時刻、実行完了、出力場所を追えるようにし、失敗を含む総所要時間も記録する。

高速化の比較では同じ参照・動作・尺・解像度・評価基準をできるだけ揃える。公式が示す高速化とこのマシンで測った速度を区別する。速度が速くても人物や動作が崩れれば同等品質の代替とは判定しない。別モデルの導入を提案するときは、比較根拠と未確認点に加え、必要なダウンロード対象を具体的に提示する。

## 漫画へ戻すとき

採用したカットのどの瞬間・画角・位置関係・間が目的に効いたかを `docs/reviews/` に残す。漫画では省略する動作、残す決め姿勢、反応コマ、読者に補完してもらう移行を検討する。映像の出来と漫画への有効性は別に評価する。

フィードバックの記録を依頼された場合だけ、[フィードバックの運用](feedback-workflow.md) に従って `docs/feedback/` へ整理する。記録するかの確認はしない。人物の絵、作品固有の台詞や設定、生成物、未整理ログ、実機の絶対パスは共通テンプレートへ配らない。配布するのはこの運用とSkill、共通化できた条件付きの知見だけとする。
