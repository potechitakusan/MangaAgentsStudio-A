# プロセスチェッカー

標準プロセスとユーザーの必須事項を照合し、実施漏れと具体的な対応をメインへ返す。指示のない演出・台詞・構図・改善案の採否はメインの裁量に残す。別エージェントを常駐させるSkillではない。

## 入口

- 作品ルートの `project.json` と `config/process-requirements.json` を確認する。標準工程の全体は `docs/knowledge/manga/08-workflow-review.md`、適用する生成方式等は作品のOPTIONと対応する知識を使う。標準文書をこのSkillへ複製しない。
- 有効な `requirements` が０件なら、登録相談を依頼された場合を除き、このSkillでの詳細な照合・進捗報告・Hooks導入をしない。既存のAGENTS.mdの必須条件は維持する。欠落・不正なJSONは０件扱いにしない。
- 保存・コマンド・入出力は `docs/knowledge/process-checker.md` を必要な箇所だけ読む。作業パスは作品ルート基準。新しい必須事項をキットの共通雛形やユーザー全体の設定へ書き戻さない。

## 必須事項を追加・変更するとき

1. ユーザーの「次から必須にしたい」「この手順を指示として覚えて」等の依頼を受けて開始する。毎回の制作後に登録を勧めたり、不満・一度限りの修正・標準的な推奨から勝手に登録しない。
2. 次の点をユーザーと具体的に相談する。既に答えられた点は再質問しない。
   - 必須にする行為と適用条件。作品固有の人物名やセリフを別作品へ持ち込まない表現にするか
   - レベルは **「指示」**（工程報告時に照合）／**「強く指示」**（AGENTS.mdへ反映し、必要ならHooksも追加）
   - これからの作業・次の改稿からか、今回の成果物にも適用するか。作品全体に１回か各ページか、いつまでに行い、どの根拠があれば実施済みとするか
   - 今の作品だけで使うか、明示的な引き継ぎ時に次の作品へもコピーするか
   - 強い指示はAGENTS.mdだけで足りるか、Hooksで報告忘れも補うか。既存の指示との重複・矛盾、創作の裁量への影響
3. 登録する具体的な文面・レベル・条件・確認時点・引継ぎ可否・反映先を提示し、明示回答を受けて登録する。最初から具体的な登録指示がそろっていれば、その指示を回答として使う。
4. **「おまかせ」なら、その範囲の文面・レベル・タイミング・反映方法をCodexが決め、理由を短く説明して登録する。** 再度一括承認を求めない。Hooksの実行信頼、権限境界、外部送信や有料利用の許可は代行しない。指定のない工程を大量に追加しない。
5. 相談を反映した１件のJSONを作品の `.work/process-checker/` に用意し、`scripts/process_checker.py add` または `replace` で登録する。元のユーザー発言・相談の詳細は作品内の同作業フォルダへ記録し、正本には再利用する指示と短い決定理由だけを置く。
6. 「強く指示」は登録と同時にAGENTS.mdの管理区間へ反映する。Hooksを選んだ場合は `install-hooks` で具体的な設定を先に提示し、今回の承諾または「おまかせ」の範囲内なら `--apply` で保存する。Codex側のレビュー・信頼はユーザーに案内し、未信頼・未確認を稼働済みと報告しない。

「次から」の指示は過去の成果物のやり直し命令にしない。適用開始を `condition` に含め、既存の完了工程へ遡及する場合だけその範囲を相談する。同じ会話中にAGENTS.mdを更新した場合も、更新箇所を読み、その場から適用範囲を守る。自動再読込だけに依存しない。

## 工程を報告するとき

- 着手・再開時に正本と既存の照合記録を読む。字コンテ完了・ネーム完了・各ページ完成・PNG提示前・引き渡し前等の節目で、その時点までに必要だった項目を照合する。「強く指示」は指定した前提工程の着手前にも確認する。
- 報告の対象IDと版を決め、指示の適用条件を判断する。前回からの未解決事項を持ち越し、工程を飛ばした報告でも、それ以前の期限の指示を確認する。修正済みのページには新しい版を付ける。引き渡し前は実際の対象ページを列挙して、各ページの最新の版に対する報告があることを確認する。
- 自己申告だけで実施済みにしない。原稿・画像・レビュー本文・生成時の入力記録・実際のユーザー回答等を読み、対象・版・内容を照合する。画像の確認が必要なら実画像を開く。参照画像の存在だけでは生成ツールへ添付した証明にならない。
- `report` へ「実施済み／未実施／未確認／ユーザー回答待ち／対象外」と理由・根拠ファイルを渡す。対象原稿とレビュー記録の両方を根拠に含めれば、変更時に再確認できる。スクリプトは内容の真偽を判定せず、ID・期限・ファイルとハッシュを管理する。
- 不足があれば、指示ID・対象・欠けている行為・根拠・次の対応をメインへ返す。関連する作業を補い、根拠を再照合する。標準から違うという理由だけで必須事項を増やさない。レビュー実施が必須でも、提案の全採用が必須になるわけではない。
- 回答待ちでは同じ質問を繰り返さず、独立した作業を進める。無関係な相談だけのターンは `noProgress` 報告で終了できる。制作を進めたのに `noProgress` で照合を回避しない。

## 次の作品への引き継ぎ

ユーザーが引継ぎ元を明示した場合だけ、キットの新規作成引数 `-ProcessRequirementsFrom` または新規作品の `import` を使う。別作品・ユーザー領域を自動探索しない。コピーするのは `carryForward: true` の指示だけ。元作品の完了記録・素材・Hooks設定・信頼・外部利用の許可はコピーしない。

引継ぎ先に指示が既にある場合は、追加・統合・置換の差分を相談する。既存作品は自動移行しない。強い指示は新しい作品のAGENTS.mdへ反映するが、Hooksはその環境で別途設定・レビューする。
