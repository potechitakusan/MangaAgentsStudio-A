# NovelAI制作のWebUI

`docs/knowledge/novelai-composed-production.md` の一括生成（要求JSON → generate → adopt → build）を、人間が画面で操作するための道具。処理はすべて作品の `scripts/novelai_batch.py`・`scripts/novelai_api.py` に任せる。WebUIは独自の生成・組版をしない。

## 起動（作品ルートで）

```powershell
python -X utf8 .agents/skills/novelai-batch-webui/novelai_webui.py
# ポートや作品を指定する場合
python -X utf8 .agents/skills/novelai-batch-webui/novelai_webui.py --port 8800 --root <作品ルート>
```

表示された `http://127.0.0.1:8765/?token=…` を利用者がブラウザーで開く。**AIエージェントはブラウザーを起動・操作しない**（URLを伝えるだけ）。終了は Ctrl+C。URLのトークンは起動ごとに変わる。

## 画面でできること

| タブ | 内容 | 呼ぶコマンド |
| --- | --- | --- |
| コマ | 要求の一覧（ページ別、採用画像のサムネイル）。場面共通の文（`input` と `base_caption` を同時に保存）、人物別本文、配置ピン（x・y、`use_coords`）、人物別の除外、除外文、幅・高さ・seed の編集。**V5の精密参照**（キャラ・衣装・絵柄等の種類、画像の相対パス、強度、サムネイル、追加Anlas）の表示・追加・変更・削除（画像の欄には、保存済みの参照ならそのパスを例として表示）。差し替え案（`p01-03b` 等）として複製。変数展開後の送信内容と語の点検の表示。候補の比較・拡大・採用・廃棄（`discarded/` へ移す）。ページ単位・全ページ・指定ページから指定ページまでの生成と、最新候補の一括採用（ページ単位・全ページ） | `generate`（`--max`）、`adopt`、`adopt-latest` |
| ページ | 最新ビルドと注記入り確認画像、組版点検の件数。コマ内の focus・zoom・rotation の表、ページ構成と組版指定のJSON編集。ページ単位・全ページのそれぞれに「PNG」と「PSD」のビルドボタン（PSDのビルドは同じ版のPNGも作る） | `build`、`build --write-psd`（`--page`／`--all`） |
| 変数 | `.env.novelai` の `NOVELAI_CHAR_`・`NOVELAI_STYLE_`・`NOVELAI_BACKGROUND_` の表示・編集・追加、使う要求の一覧、その要求の生成、templatize（確認／適用）。以前の版で `.env`・`.secrets/` に置いた変数・補助設定が残っている場合は、その表示と `.env.novelai` へ移すボタン。左側に、プロンプトを一括で調整できるようにするためのAIエージェントへの依頼文の例を表示し、変数が１個もない場合は「変数を追加」の上に赤い太字でも表示する。画面下部の**精密参照の一括設定（V5）**（下記） | `env-set`、`templatize`、`env-migrate` |
| プレビュー | 各ページの最新ビルドをページ送り（右から左。← が次） | ― |
| 実行ログ・接続 | 直前の操作のコマンドと出力（実行中も1.2秒ごとに更新。自動スクロールのチェックをONにすると更新のたびに一番下を表示）、実行中の操作の中止、**実行結果の整理**（下記）、キーの読込確認、契約照会、list。失敗したときの「ログを開く」で、この画面が表示される。右上の状態表示には生成の進み具合（例：3/39件目 p01-03）が出て、クリックするとログを開く | `key-status`、`status`、`list` |

各操作は、同じことを端末で行うコマンドをログに表示する（`output/webui/logs/` にも保存）。

## 精密参照の一括設定（変数タブの下部）

画像の欄はコマ画面と同じ（`input/`・`assets/` の候補から選ぶか手入力、サムネイル、保存済みのパスを例に表示）。

- **絵柄（全コマの既定）**：絵柄は漫画全体で統一するため、既定では各コマで指定せず、ここで画像と強度を保存する（`input/novelai/reference-defaults.json`）。生成時に `novelai_batch.py` が、絵柄（絵柄・キャラ＋絵柄）を指定していないV5のコマの先頭へ足す。コマで絵柄を指定したコマは、そのコマの指定で上書きする。既定を使うコマの件数と、上書きしているコマを表示する。設定すると参照のなかったコマも参照付き（１枚につき追加5 Anlas）になり、0 Anlasの生成には含められない。コマ画面の参照欄にも、既定を使うかどうかと追加Anlasを表示する。作品の `scripts/` が配布版0.5.7以降で使える。
- **キャラ・衣装の画像の置換**：「キャラ画像一覧表示」「衣装画像一覧表示」で、各コマの要求JSONに書かれた画像ごとに、種類と使うコマを一覧にする（キャラの一覧はキャラ＋絵柄の種類も含む。`${…}` は書いたままの文字）。一覧の説明の下に、キャラ・衣装を大きく変えた場合はプロンプトの特徴・衣装の説明（変数や人物別の文）も直すよう赤い太字で表示する（元の説明が残ると画像がプロンプトの方に引っ張られる。利用者の観察）。変更する画像だけ変更後の画像を選び、「置換」でその画像を使う全コマを書き換える（変更前の内容は `output/webui/history/` に残し、操作は `records.log` に記録）。置換後に一覧の別の画像と同じになり、元の区別がつかなくなる場合は「変換後の画像が既に採用されているものもあります、よろしいですか？」と確認し、OKの場合だけ置換する（サーバーも確認なしの置換を止める）。置換後に各コマで指定した画像は、そのコマの指定になる。実行中の操作がある間は保存・置換できない。

## 実行結果の整理（実行ログ・接続タブ）

要求ID（例 `p07-03`）を入れて「点検」、または「全コマから結果不明を探す」で使う。**ファイルは削除せず、同じフォルダのサブフォルダへ移す**（日時・候補番号・識別子でフォルダを分け、`moved.json` に操作を残す。操作は `output/webui/logs/records.log` にも記録）。復元した候補の `moved.json` は `output/webui/history/records/` へ保管する。実行中の操作がある間は整理できない。

| 状態 | 対応 |
| --- | --- |
| 結果不明（実行記録はあるが画像がない。`novelai_batch.py` が「結果不明の実行記録があります…failed/ へ移してから」で止まる） | NovelAIの画像の履歴とAnlasの消費を確認し、「確認した」にチェックして `failed/` へ移す。画像ができていた場合は、その画像を `rNNN.png` として同じフォルダに保存すれば結果として扱える（移さない） |
| 不要な候補 | 「廃棄」で `discarded/` へ移す。採用中の画像は廃棄できない。`discarded/` から「戻す」で元の場所へ戻せる（同名があれば戻さない） |
| 止まらない操作 | 「中止」（実行中の操作の欄）。生成の送信中に中止すると、その記録は結果不明になるので上の手順で確認する。ビルドを中止した場合は、未完成の版フォルダ（`build.json` がない）を確認して片づける |

端末では、NovelAIの結果不明の記録を `python -X utf8 scripts/novelai_batch.py move-unknown --ids <要求ID> --confirm-checked --note '確認した内容'` で同じように `failed/` へ移せる（`--confirm-checked` なしは対象の表示だけ）。

`failed/`・`discarded/` の中は候補の番号の数え方・一覧の対象外になる（`novelai_batch.py` はフォルダ直下だけを数える）。

## 守ること

- **生成の費用確認は省略しない。** 「生成する」には、0 Anlasを確認したチェックと確認内容（`--cost-note`）が必須。V5の利用上限のチェックはV5のとき付ける。WebUIからの有料生成（`--allow-anlas`）は、下の条件を満たすV5の精密参照の追加料金だけで、ほかの有料利用は利用者の明示指示のもとで端末から行う。チェックは確認済みの宣言で、WebUIやスクリプトが無料を保証するものではない。
- **精密参照付きの生成（参照画像1枚につき追加5 Anlas）** は、次をすべて満たす場合だけ送る。満たさなければサーバーが送信前に止める。
  - 対象が精密参照付きのコマだけ。参照なしのコマと混ざる対象では、生成画面で「参照なし」「精密参照付き」のどちらかを選ぶ（0 Anlasの生成に参照付きのコマは含められない）。
  - 参照を除いた要求が、0 Anlasの生成と同じ条件（28steps以下・1,048,576画素以下・１枚・ほかの追加機能なし）を満たす。
  - 利用者が「今回の範囲でAnlasの消費を許可する」チェック・今回の上限Anlas・V5の利用上限の確認・確認内容をすべて入力し、追加料金の見込みが上限以下である。許可と上限Anlasは既定では記憶しない。利用者が生成画面で「精密参照の入力内容を記憶」をONにした場合だけ、起動ごとのトークン（URL）単位で次回も入れておく（OFFにして閉じると記憶を消す）。
  - 送信は `--allow-anlas` と `--confirm-v5-allowance` の併用で行い、契約照会の結果がOpus契約や利用上限の不足を示せば止まる。照会は目安10回ごとのため、途中で不足した場合を必ず検出できるとは限らない。
  - 上限は1回の実行の見込みに対するもので、前回までの消費や作り直しの合計は数えない。生成本体の料金は別で、参照付きの生成にOpusの無料条件が適用されるかは未確認。まず1コマで、Anlas残高の前後を比べる。
- AIエージェントは、利用者の明示の許可がないまま、上のチェックや上限の入力、入力内容の記憶を付けるよう案内しない。使うかの確認・参照画像の用意・記録は `docs/knowledge/novelai-composed-production.md` の「V5の精密参照を使うか確認する」に従う。
- 生成画面のチェック（0 Anlas・V5の利用上限・警告の確認）と上限件数は、**起動ごとのトークン（URL）単位でブラウザーに記憶する**。サーバーを起動し直して新しいURLで開くと、古いトークンの記憶は消える。記憶したチェックも確認済みの宣言なので、条件（モデル・寸法・steps・追加機能）を変えた場合や利用上限が少ない場合は外して確認し直す。
- 1回の上限件数は既定30件（`novelai_batch.py` の既定）。全ページなど30件を超える対象は、生成画面の「１回の上限件数」（`--max`、1～1000）を増やす。送信間隔（既定3秒）・失敗時に止まって自動再送しない扱い・結果不明の記録の扱いは `novelai_batch.py` のまま。同時に１つの操作だけ実行する。
- APIキーは読まない・表示しない（変数は `novelai_batch.read_variables` が許可した接頭辞だけを扱う）。画像は `output/`・`input/`・`assets/`・`templates/onomatopoeia/` の画像だけを返す。
- 127.0.0.1 でだけ待ち受け、起動時のトークンと Host を確かめる。他の端末へ公開しない。
- JSONを保存するたびに、前の内容を `output/webui/history/` に残す。保存前に JSON の形（`input`・`parameters`、ページ構成の `schema_version`・`panels`）を確かめる。
- 画面での編集も、作品の制作手順（要求プロンプトの組み立て、送信前の内容照合、作画後の照合表、組版後の点検、PNG確認・PSD作成の判断）を置き換えない。生成後は画像を開いて照合する。
- 変数化（`.env.novelai` への取り込み）は、作品の手順どおり人間の依頼があった場合に、変数名と値を確認してから行う。

## 前提と限界

- Python 3.10以上の標準ライブラリだけで動く。build と、精密参照を含む要求の送信なし確認・生成は作品の既存要件（Pillow）を使う。
- 対応するのは配布版0.5系の `novelai_batch.py`（`read_variables`・`request_files`・`candidates`・`load_adopted`・`resolved_request`・`lint_prompt` 等の関数と、list・vars・env-set・templatize・generate・adopt・adopt-latest・build の各コマンド）。関数名が変わった版では起動時にエラーになる。精密参照の編集には配布版0.5.6以降、画面からの参照付き生成には0.5.7以降の作品の `scripts/` が必要（古い版では、画面に表示して止まる）。
- 精密参照の画像は作品内のファイルを指定する（アップロード機能はない）。画像の欄は手入力でき、候補には `input/`・`assets/` の画像（PNG・JPEG・WebP。隠しフォルダ・隠しファイルを除く）すべてと、ページに属さない要求（人物試作など）の採用画像が出る。フォルダの一覧は最初の表示時に作るので、ファイルを追加したら画面上部の「候補画像を更新」で取り直す（編集中の入力は消えない）。採用画像は表示のたびに `adopted.json` から読む。採用画像の候補はその時点の候補ファイル（`output/novelai/candidates/…/rNNN.png`）を指すため、試作を採用し直しても指定済みの参照は変わらない。版を固定して使う場合は `input/novelai/references/` へ版の付いた名前で保存する。ページのコマの採用画像など、ほかの `output/` の画像はパスを手入力する。
- 要求JSONの人物を追加・削除する編集、`v4_prompt` がない要求の人物別入力、steps・モデルの変更は画面に出していない（JSONを直接編集するか `novelai_compose.py` で組み立て直す）。
